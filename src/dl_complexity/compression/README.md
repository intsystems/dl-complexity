# `compression`: преобразования весов и сообщения моделей

_Карта интерфейсов преобразования, бинарного кодека и Matrix-Project._

---

`compression` содержит два разных механизма. `ModelTransform.apply(model)` создаёт независимую модель с изменёнными весами. `ModelCodec.encode/decode` строит реальное бинарное сообщение и восстанавливает модель из него. Преобразование весов само по себе не сообщает длину кода и не доказывает границу обобщения.

## 🗂️ Интерфейсы и объекты

| Файл | Публичный интерфейс | Вход → выход |
| --- | --- | --- |
| [`base.py`](base.py) | `ModelTransform.apply` | `nn.Module → nn.Module`, без изменения исходной модели |
| [`base.py`](base.py) | `ModelCodec.encode`, `decode` | Модель → `EncodedModel` → новая модель |
| [`base.py`](base.py) | `EncodedModel` | Обёртка над `payload: bytes`, свойство `length_bits = 8 * len(payload)` |
| [`pruning.py`](pruning.py) | `MagnitudePruning(fraction).apply` | Глобальное зануление малых по модулю весов |
| [`low_rank.py`](low_rank.py) | `LowRankApproximation(rank).apply` | Усечение SVD и восстановление плотных матриц |
| [`quantization.py`](quantization.py) | `uniform_quantize`, `QuantizedTensor.dequantize`, `UniformQuantization.apply` | Аффинная сетка, индексы и восстановление весов |
| [`codecs.py`](codecs.py) | `BinaryModelCodec` | Самоописываемое сообщение с выбранным режимом тензоров |
| [`arora.py`](arora.py) | `matrix_project`, `AroraMatrixProject`, связанные артефакты | Конечные коэффициенты случайной проекции и восстановленный предиктор |

`ModelTransform` и `ModelCodec` — независимые ABC, не подклассы `ComplexityEstimator`. `MagnitudePruning`, `LowRankApproximation`, `UniformQuantization` и `AroraMatrixProject` наследуют `ModelTransform`. `BinaryModelCodec` наследует `ModelCodec`. У них нет общего `estimate`: численную оценку из их результата получает [`coding`](../coding/README.md) либо [`bounds`](../bounds/README.md).

Конфигурация передаётся в конструкторы. `apply`, `encode`, `decode` и `project` выполняют работу явно. `EncodedModel`, `QuantizedTensor`, `MatrixProjection` и `ProjectedModel` — записи с данными, а не обучаемые оценщики. `frozen=True` защищает присваивание полей, но не содержимое вложенных тензоров и словарей.

## 🔧 Как меняются веса

### `MagnitudePruning`

`apply` копирует модель, собирает параметры с `ndim >= 2` в общий вектор модулей и сортирует его стабильным `argsort`. Ровно `floor(fraction * N)` позиций зануляются. При равных модулях порядок определяется порядком параметров и плоским индексом. Bias и одномерные параметры не участвуют. Для совместной сортировки параметры должны находиться на одном устройстве.

Архитектура остаётся плотной. Нулевые веса начнут сокращать сообщение только при кодеке, который хранит маску и ненулевые значения. Fine-tuning и sensitivity-pruning не выполняются.

### `LowRankApproximation`

Для каждой двумерной матрицы `float32/float64` вычисляется economy SVD с `full_matrices=False`. Затем сохраняется в модели плотная реконструкция

$$
A_r = (U_{:,1:r}\,S_{1:r})(V_h)_{1:r,:},\qquad
V_h=V^{\mathsf T},\qquad r = \min(\texttt{rank},m,n).
$$

SVD вычисляет все `min(m, n)` сингулярных направлений, даже при маленьком выбранном ранге. Свёрточные ядра автоматически не разворачиваются в матрицу. В `nn.Module` остаётся плотный вес прежней формы, поэтому меньший ранг здесь не означает меньшую стоимость forward или меньше байтов при dense-кодировании.

### `uniform_quantize` и `UniformQuantization`

`uniform_quantize(tensor, bits)` поддерживает `1..16` бит и конечный непустой floating tensor. В `float64` вычисляются минимум `a`, максимум `b` и шаг `s = (b-a)/(2^bits-1)`. Для константного тензора используется `s=1`. Коды получаются округлением к ближайшему целому с clamp на допустимый диапазон. `QuantizedTensor.dequantize()` вычисляет `a + s * codes` и возвращает исходный `dtype`.

`QuantizedTensor.codes` хранится как `int64`, а не как уже упакованные биты. Таблица из `2^bits` значений не создаётся. `UniformQuantization.apply` копирует модель и квантует её непустые floating-параметры, оставляя буферы без изменения. Обучение с квантованием и градиенты через округление не реализованы.

## 📦 Устройство `BinaryModelCodec`

`BinaryModelCodec(encoding="dense", transform=None, bits=8, rank=1)` сначала применяет необязательный `ModelTransform`, затем описывает архитектуру и кодирует весь `state_dict`. Доступны встроенные `Sequential`, `Linear`, `Conv2d`, `BatchNorm1d/2d`, перечисленные в [`_architecture`](codecs.py) активации, pooling, `Flatten`, `Dropout` и `Identity`. Произвольный `forward`, подклассы вне белого списка, локальные forward hooks, связанные параметры и общее хранилище тензоров состояния отклоняются.

Сообщение состоит из:

| Часть | Размер | Содержимое |
| --- | --- | --- |
| Magic/version | 5 байт | `DLCM` и байт версии `1` |
| Длина заголовка | 8 байт | Big-endian длина JSON |
| Заголовок | `H` байт | Канонический JSON: архитектура, training flags, параметры конструкторов, имена, dtype, формы, режимы и длины частей, requires-grad flags |
| Части тензоров | `Σ M_i` байт | Данные согласно выбранным режимам |

Полная длина равна `8 * (13 + H + Σ M_i)` бит. Кодек работает на little-endian host, а не предполагает неучтённый внешний декодер архитектуры.

| Режим | Представление тензоров | Что восстанавливается |
| --- | --- | --- |
| `dense` | Байты каждого тензора | Численные значения без потерь |
| `sparse` | Для floating-тензора: упакованная битовая маска и ненулевые значения. Остальные тензоры dense | Численные значения без потерь, но знак `-0` канонизируется |
| `low_rank` | Для двумерного `*.weight`: два SVD-фактора `[m, r]` и `[r, n]`. Остальное dense | Обычно приближённые плотные веса |
| `quantized` | Для непустых floating-тензоров: `minimum`, `scale` и упакованные индексы. Остальное dense | Приближённые значения на сетке |

`decode` проверяет magic, размер заголовка, метаданные, уникальность имён, размеры частей, padding и отсутствие хвоста. Он строит архитектуру на `meta`, присваивает восстановленные CPU-тензоры и возвращает самостоятельную модель с сохранёнными flags. `model_factory`, если передан, служит структурной проверкой, а не бесплатной заменой сериализованной архитектуры. Различие только в training flags при этой проверке допускается.

Формат не использует pickle, но декодер не является изолированной средой для враждебных сообщений: ограничения на ресурсы из недоверенного заголовка отдельно не реализованы.

### Внутренние функции кодека

Все имена с начальным `_` в `codecs.py` — детали формата, не отдельные публичные расширения.

| Имена | Вычисление |
| --- | --- |
| `_architecture`, `_build_architecture`, `_structure_only` | Описание встроенной архитектуры, её сборка и удаление mode-полей для сравнения схем |
| `_raw`, `_from_raw` | Перевод в независимые CPU-байты и восстановление формы/dtype из точного количества байтов |
| `_pack`, `_unpack` | Фиксированная ширина целочисленных кодов, нулевой padding до целого числа байтов и проверка канонического padding |
| `_tensor_message`, `_tensor_decode` | Выбор режима одного тензора, запись метаданных/частей и обратное преобразование |

**Ограничение упаковки:** `_pack` и `_unpack` не очищают уже обработанные биты аккумулятора. Python integer растёт до размера сообщения. Линейное число итераций циклов не означает линейную битовую стоимость: сдвиги растущих больших целых могут дать квадратичную суммарную работу. Это ограничение производительности текущего формата, а не дополнительный математический штраф к MDL.

## 🎲 Matrix-Project и конечный предиктор Arora

`matrix_project(A, helpers, alphabet)` получает матрицу `A: [m, n]`, фиксированные знаковые матрицы `helpers: [K, m, n]` и возрастающий конечный алфавит `alphabet: [r]`. Он вычисляет

$$
z_k = \langle A,M_k\rangle_F,\qquad
j_k = \arg\min_j |z_k-a_j|,\qquad
\widehat A = \frac1K\sum_{k=1}^K a_{j_k}M_k.
$$

При равных расстояниях `argmin` выбирает меньший индекс. Возвращается `MatrixProjection` с индексами, копиями helpers и алфавита, а также максимальной ошибкой округления коэффициента. Свойство `reconstructed` заново вычисляет сумму, оно не кешируется. Это не хранение обычной low-rank факторизации.

`make_projection_helpers(model, n_projections, seed=...)` создаёт знаки через локальный CPU-генератор и переносит их на dtype/device параметров. Функция использует формы весов, но не их значения. Сам факт вызова с `seed` не доказывает независимость helpers от обучающей выборки: подбор seed после экспериментов нарушает это условие.

`nominal_projection_count(epsilon, eta)` возвращает `ceil(-ln(eta) / epsilon²)`. Это номинальный бюджет, а не сертификат ошибки после конечного квантования коэффициентов.

`AroraMatrixProject.project(model)` копирует модель, применяет `matrix_project` к её матрицам и возвращает `ProjectedModel`. `apply(model)` возвращает только модель и отбрасывает удобный контейнер артефактов. Для последующей границы нужен путь `project`.

`ProjectedModel` хранит модель, словарь проекций и закреплённую JSON-схему. `decode()` повторно проверяет схему и индексы, сверяет веса с реконструкцией и строит новый предиктор из схемы и конечных индексов. Для этого пути допускаются только точные встроенные `Sequential`, `Linear` без bias, `ReLU`, `Identity`, `Flatten`. Hooks, overrides, буферы, лишние параметры и aliases отклоняются. Защита находится во внутренних `_arora_schema` и `_validated_reconstruction`.

`parameter_count` артефакта — число конечных коэффициентов `q = Σ K_l`, а `values_per_parameter` — верхняя граница размера их алфавита. Helpers могут занимать `O(Σ K_l P_l)` памяти. Этот контейнер не является коротким бинарным сообщением `BinaryModelCodec` и не считает длину helpers в байтах. Связь с условной теоремой и проверкой искажения описана в [карте `bounds`](../bounds/README.md).

## ⏱️ Стоимость операций

Пусть `P` — общее число скаляров модели, `N` — число скаляров в текущем тензоре, `L` — число модулей, `H` — объём метаданных, `d = min(m,n)`. Все оценки ниже — анализ операций, не benchmark.

| Операция | Время | Память |
| --- | --- | --- |
| Конструкторы, `EncodedModel.length_bits` | `O(1)`, кроме копирования mapping helpers `O(L)` | Конфигурация и ссылки |
| `MagnitudePruning.apply` | `O(P + N log N)` из-за полной сортировки | Копия модели `O(P)`, векторы/маски `O(N)` |
| `LowRankApproximation.apply` | `O(P + Σ m n d + Σ m n r)` | Копия модели, economy-факторы `O((m+n)d)`, реконструкция `O(mn)` |
| `uniform_quantize`, `dequantize` | `O(N)` | `O(N)` floating-значений и `int64` кодов |
| `UniformQuantization.apply` | `O(P)` | Копия модели и рабочие тензоры текущего параметра |
| `_raw`, `_from_raw` | `O(числа байтов)` | Байтовые копии. `_raw` также создаёт Python-список элементов byte-view |
| `_pack`, `_unpack` | Линейное число итераций, потенциально квадратичная битовая работа | Растущий bigint, сообщение и список кодов |
| `_architecture` | До `O(L² + H)` из-за повторных обходов вложенных поддеревьев | `O(H)` и стек рекурсии |
| `_build_architecture`, `_structure_only` | `O(L + H)` | Метаданные, новая структура. Параметры при сборке сначала на `meta` |
| `_tensor_message` | Dense/sparse: линейные тензорные операции. Low-rank: `O(m n d)`. Quantized: `O(N)` плюс упаковка | Части сообщения и промежуточные тензоры выбранного режима |
| `_tensor_decode` | Dense/sparse/quantized: линейные тензорные операции плюс распаковка. Low-rank: `O(m n r)` | Плотный результат `O(N)` и части текущего режима |
| `BinaryModelCodec.encode/decode` | Сумма метаданных, выбранных операций тензоров и сериализации | Сообщение, заголовок, модели и временные копии, не потоковая обработка |
| `matrix_project` | `O(KP + Kr)` для матрицы с `P=mn` | Helpers `O(KP)`, broadcast-расстояния `O(Kr)`, индексы и алфавит |
| `MatrixProjection.reconstructed`, `_validated_reconstruction` | `O(KP + r)` с проверками | Временное произведение `O(KP)` и матрица `O(P)` |
| `make_projection_helpers`, `AroraMatrixProject.project/apply` | Генерация `O(Σ K_l P_l)`, проекция дополнительно сравнивает `K_l r` расстояний | Helpers, копии модели и проекционные артефакты |
| `ProjectedModel.decode` | Проверки схемы плюс `O(Σ K_l P_l)` | Свежая модель, реконструкции и helpers |
| `parameter_count`, `values_per_parameter` | `O(1)` для одной матрицы, `O(L)` для `ProjectedModel` | `O(1)` |
| `nominal_projection_count` | `O(1)` | `O(1)` |

На GPU извлечение минимума, максимума и булевых результатов проверок может синхронизировать устройство. Transform и кодирование выполняются без дифференцируемого пути к исходным весам. Уменьшение числа хранимых коэффициентов нельзя отождествлять с уменьшением пикового расхода памяти подготовки.
