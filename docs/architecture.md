# Архитектура библиотеки

## Общий поток данных

```text
nn.Module + likelihood        Готовые статистики / posterior / ledger
          |                                  |
     ModelContext + DataSource               |
          +-----------------+----------------+
                            |
                    check -> estimate
                            |
                    ComplexityResult
                  /         |          \
             quantities  assumptions   config / provenance / time
```

`ModelContext` хранит исходную модель, объявленное правдоподобие и необязательный
`TrainingRecipe`. Создание контекста не обучает сеть. Loss и likelihood —
разные входы: произвольная функция потерь не задаёт нормированное распределение.
`DataSource` описывает пары `(inputs, targets)` и число наблюдений.

Каждый оценщик наследует `ComplexityEstimator` и имеет `check` и `estimate`.
`check` проверяет метаданные без forward, обучения и чтения итератора.
Численные значения дополнительно проверяются при оценке. `READY` не удостоверяет
MLE/MAP, сходимость posterior или статистические предпосылки.

| Слой | Объекты | Ответственность |
|---|---|---|
| Ядро | `ModelContext`, `DataSource`, `Quantity`, `Provenance` | Модель, данные, единицы и объявленное происхождение |
| Оценщики | `criteria`, `bayesian`, `coding`, `bounds`, `diagnostics` | Проверки и формулы |
| Подготовка | `prepare_*`, `run_training` | Явное обучение, сэмплирование, кривизна и история предсказаний |
| Сжатие | `ModelTransform`, `ModelCodec` | Преобразование весов, кодирование и декодирование |
| Композиция | `ComplexitySuite`, `EvaluationOutcome` | Именованные вызовы и отдельные ошибки методов |

## Два способа оценки

Прямой путь поддерживается там, где достаточно текущих весов и данных,
например у AIC/BIC/HQIC. Альтернативный путь принимает типизированные входы
без повторного прохода по модели:

```{doctest}
>>> from dl_complexity.criteria import BIC, FitStatistics
>>> result = BIC().estimate(inputs=FitStatistics(-100.0, k=3, n=100))
>>> round(result.primary.value.item(), 6)
213.815511
>>> result.primary.unit
'native_ic'
```

У prequential-ветки явно разделены:

1. `prepare_blockwise` / `prepare_online` / `prepare_replay`: обучение и запись
   `PrequentialLedger` с суммарными NLL блоков, вычисленными **до** обновления.
   Сами вероятности отдельных наблюдений журнал не сохраняет.
2. `BlockwisePrequential` / `OnlinePrequential` / `ReplayPrequential`:
   проверка журнала и суммирование его стоимостей.

Финальный checkpoint не восстанавливает прошлые вероятности. Для этой ветки
нельзя заменить подготовку оценкой уже обученной сети на всей выборке.

## Значение результата

`ComplexityResult.quantities` хранит именованные `Quantity`; `primary` выбирает
основную величину. Каждая величина имеет единицу и нормировку. Кодовые длины
переводятся `bits = nats / ln(2)`; `native_ic` сохраняет шкалу критерия,
а риск — шкалу вероятности. Нормировка на наблюдение задаётся явно.

`config`, `assumptions` и `provenance` описывают настройки, условия и объявленные
идентификаторы. Строковые IDs не являются хешами весов или данных.
`elapsed_seconds` измеряет вызов оценки после preflight; подготовку prequential
журнала нужно измерять отдельно. Это также не синхронизированный GPU benchmark.

`ComplexitySuite` последовательно вызывает именованные оценщики. Он не обучает
общую модель, не кеширует статистики и не строит универсальное ранжирование
разных математических величин. Готовые входы можно разделять явно.
