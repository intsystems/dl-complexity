# Эксперименты и проверка результатов

## Что уже можно воспроизвести

1. Аналитические эталоны AIC/BIC/HQIC, WAIC, Gaussian evidence, VI/WBIC,
   prequential и компрессионной ветки находятся в pytest.
2. `examples/quickstart.py` проверяет общий API на маленькой модели.
3. `examples/waic_wbic_mlp.py` проводит teacher–student эксперимент с MALA.
4. `examples/prequential_demo.py` обучает MLP во всех трёх последовательных
   протоколах с калибровкой и без неё, сохраняя воспроизводимый JSON.

Отдельного общего benchmark runner, результатов MNIST/Fashion-MNIST и финальной
таблицы корреляций в текущем репозитории нет. Ниже — протокол следующего этапа,
а не описание уже выполненного исследования.

## План сравнения prequential-протоколов

| Фактор | Что фиксировать / изменять |
|---|---|
| Данные | Train/validation/test IDs, размер train, преобразования только по train |
| Порядок | Одну перестановку train на seed, общую для всех вариантов |
| Модель | Архитектуру, начальные веса и число параметров |
| Обучение | Optimizer, learning rate, steps, batch size, критерий остановки |
| Blockwise | Начальный префикс и список правых границ |
| Online/replay | Размер нового блока, replay size/policy и seed |
| Калибровка | Начальный T, steps, learning rate, отдельный экземпляр на запуск |
| Бюджет | Время всей подготовки, число обновлений и просмотренных объектов |

Проведите несколько заранее выбранных seeds, а затем изменяйте один фактор:
ширину/глубину сети, размер train, регуляризацию или долю случайных меток.
Для replay полезно сравнить `replay_size=0` и положительные размеры при
одинаковом числе optimizer steps и отдельно учесть дополнительную обработку объектов.

## Метрики и интерпретация

Сохраняйте total/initial/predictive bits, bits per observation, train/test NLL,
generalization gap, время и пик памяти. Для готового журнала отдельно фиксируйте
дешёвое время суммирования: оно не заменяет стоимость обучения.

При изменении `n` показывайте и total, и нормированную стоимость. Для архитектур
с одним `n` анализируйте ранги каждого метода отдельно, например Spearman
с test NLL, и вариацию между seeds. Не объединяйте границу риска, evidence
и информационный критерий в одно среднее число.

Гиперпараметры и схему калибровки выбирайте без test-меток. В online/replay
новые train-метки допустимы только после записи их NLL. В blockwise текущая
реализация подгоняет калибратор на прошлом train-префиксе; независимая
validation-калибровка требует отдельно заданного протокола.

## Проверки перед исследованием

```bash
python -m pytest -q
python -m sphinx -b doctest -W docs docs/_build/doctest
```

Ветке prequential соответствуют `tests/test_coding.py`, аналитические тесты
в `tests/test_analytical_codes_bounds.py` и интеграция в
`tests/test_prequential_demo.py`. Тесты проверяют формулы и порядок операций;
они не доказывают, что любой callback или новый датасет удовлетворяет условиям метода.

Наличие тестов не подтверждает coverage > 90%. Это отдельная цель проекта,
для которой нужен измеренный отчёт покрытия.
