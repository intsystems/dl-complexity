## Запуск и выбор тестов

Команды выполняются из корня репозитория в окружении с библиотекой, PyTorch и
pytest. Требования к версиям указаны в [pyproject.toml](../pyproject.toml).
Внешние данные скачивать не нужно: входы создаются в самих тестах.

Запустить весь набор:

```bash
python -m pytest -q
```

Запустить только примеры с аналитическим ответом:

```bash
python -m pytest -q -k analytical
```

Тесты входят в репозиторий и исходный архив пакета (`sdist`). В устанавливаемом
wheel-файле тестового набора нет.

## Информационные критерии

Все `ln` обозначают натуральный логарифм. Кодовые длины выражены в натах (`nats`)
или битах (`bits`), причём `bits = nats / ln(2)`. AIC, BIC и HQIC сохраняют
собственную шкалу `native_ic`. Нормы весов и границы риска имеют другой смысл,
поэтому значения разных семейств нельзя ранжировать как одну меру сложности.
Там, где доступна нормировка на наблюдение, тесты отдельно проверяют деление
полной оценки на число наблюдений.

### Запустить первый пример

```bash
python -m pytest tests/test_analytical_criteria.py -q -k gaussian_mean_mle_known_variance
```

Расчёты и проверки двух способов вызова находятся в
[test_analytical_criteria.py](test_analytical_criteria.py).

### AIC, BIC и HQIC на нормальной модели

Пусть наблюдения `y=(1,2,4,5)` независимы и имеют нормальное распределение
с неизвестным средним и известным стандартным отклонением `σ=1`.
Оценка среднего по максимуму правдоподобия (MLE) равна `μ̂=3`.
Число наблюдений `n=4`, сумма квадратов остатков `RSS=10`, число оцениваемых
параметров `k=1`. Полный логарифм правдоподобия `ℓ` и критерии равны:

$$
\ell(\hat\mu)=-\frac n2\ln(2\pi\sigma^2)-\frac{RSS}{2\sigma^2},\quad
AIC=-2\ell+2k,\quad BIC=-2\ell+k\ln n,\quad HQIC=-2\ell+2k\ln\ln n.
$$

Все три критерия используют одно правдоподобие. Различается штраф за число
параметров:

| Метод | Ожидаемое значение в `native_ic` |
| --- | ---: |
| AIC | 19.35150826563738 |
| BIC | 18.73780262675727 |
| HQIC | 18.00477678559394 |

В PyTorch постоянное среднее можно представить линейным слоем с одним весом
и единичными входами. Вес задаётся аналитическим решением, поэтому цикл
обучения здесь не нужен:

```python
import torch
from torch import nn

from dl_complexity import DataSource, ModelContext
from dl_complexity.criteria import AIC, BIC, HQIC
from dl_complexity.integrations.torch import GaussianLikelihood

x = torch.ones(4, 1, dtype=torch.float64)
y = torch.tensor([[1.0], [2.0], [4.0], [5.0]], dtype=torch.float64)
model = nn.Linear(1, 1, bias=False, dtype=torch.float64)
with torch.no_grad():
    model.weight.fill_(3.0)

context = ModelContext(model, likelihood=GaussianLikelihood(sigma=1.0))
data = DataSource(((x, y),), n_observations=4)

for method in (AIC(), BIC(), HQIC()):
    result = method.estimate(context, data=data)
    print(result.method, f"{result.primary.value.item():.12f}", result.primary.unit)
```

Ожидаемый вывод с округлением до 12 знаков:

```text
AIC 19.351508265637 native_ic
BIC 18.737802626757 native_ic
HQIC 18.004776785594 native_ic
```

`estimate` возвращает `ComplexityResult`. Поле `primary` содержит основное
значение (`value`), единицу (`unit`) и нормировку (`normalization`). В
`quantities` хранятся именованные значения, включая составляющие оценки.
Для BIC это `bic`, `deviance` и `penalty`. Условия расчёта записаны в `assumptions`.

Если логарифм правдоподобия уже вычислен, модель и данные передавать не нужно:

```python
import math

from dl_complexity.criteria import BIC, FitStatistics

stats = FitStatistics(
    log_likelihood=-2 * math.log(2 * math.pi) - 5,
    k=1,
    n=4,
)
result = BIC().estimate(inputs=stats)
print(f"{result.primary.value.item():.12f}")  # 18.737802626757
```

Один объект `stats` можно использовать в AIC, BIC и HQIC без повторного прохода
модели. Тесты сравнивают оба способа вызова с одним аналитическим эталоном.

Если дисперсия тоже оценивается по данным,
используется `σ̂²=RSS/n` и явно указывается `k=2`. По значению аргумента `sigma`
библиотека не может определить, была ли дисперсия известна или оценена.

В примере линейной регрессии со свободным членом решение метода наименьших
квадратов (OLS) вычисляется отдельно через центрированные суммы. Тест проверяет
нормальные уравнения и правдоподобие при известной дисперсии шума.

### Модель Бернулли: число весов и число параметров

Для `s=6` единиц из `n=8` оценка вероятности равна `p̂=3/4`.
Тогда `ℓ=6 ln(3/4)+2 ln(1/4)` и `BIC=11.07680385558077`.

Модель хранит два логита, но вероятность класса определяется их разностью.
Независимый статистический параметр один, поэтому оценщик создаётся как
`BIC(parameter_count=1)`. Этот параметр задаёт статистическую размерность
вместо числа хранимых весов. Та же оценка проверяется после сохранения
и повторной загрузки весов.

### WAIC: две гипотезы о вероятности

Рассмотрим две гипотезы о вероятности единицы: `p=1/4` и `p=3/4`.
Их априорные вероятности равны `1/2`. После наблюдений `(0,1,0,1)` апостериорные
вероятности также равны `1/2`.

В `PosteriorLogLikelihood` передаётся матрица размера `S × N`: строка соответствует
гипотезе, столбец — наблюдению. Элемент `L[s,i]=ln p(y_i|θ_s)` содержит натуральный
логарифм правдоподобия наблюдения `i` при гипотезе `s`.
Здесь `N=4`, а `S` принимает значения `2,4,32`.
Каждая из двух гипотез занимает ровно `S/2` строк. Это детерминированное
перечисление апостериорного распределения.

В формуле WAIC2 величина `lppd` — сумма логарифмов усреднённых по гипотезам
правдоподобий отдельных наблюдений. Штраф `p_WAIC` — сумма выборочных дисперсий
их логарифмов по строкам матрицы. В этом примере:

$$
lppd=N\ln(1/2),\quad
p_{WAIC}=\frac{S}{S-1}\frac{N(\ln3)^2}{4},\quad
WAIC=-2(lppd-p_{WAIC}).
$$

| Число строк `S` | Ожидаемый WAIC |
| ---: | ---: |
| 2 | 10.37297328772989 |
| 4 | 8.763708006646448 |
| 32 | 8.036943040995862 |

Множитель `S/(S−1)` соответствует выборочной дисперсии с `ddof=1`, используемой
в реализации. Поэтому ответ зависит от `S`, хотя доли двух гипотез одинаковы.
Тест проверяет эту поправку на заданной матрице, без запуска MCMC.

## Байесовские оценки

В [test_analytical_bayesian.py](test_analytical_bayesian.py) разобраны три метода
для модели с нормальным правдоподобием и нормальным априорным распределением
параметров (prior). Для этой модели можно точно вычислить
маргинальное правдоподобие, или evidence: `Z=∫p(y|θ)p(θ)dθ`.
Оно служит эталоном для KFAC-Laplace и вариационной оценки. WBIC на конечной
выборке даёт другое значение, которое ниже рассчитывается отдельно.

### KFAC-Laplace: точный интеграл

В линейной модели `Y=X_aug W+ε` шум имеет распределение `ε~N(0,σ²I)`.
Здесь `n` — число наблюдений, `d` — число столбцов матрицы `X_aug`,
`c` — число выходов. Если модель содержит свободный член, `X_aug` включает
столбец единиц. Для каждого выхода задаётся независимый prior
`w~N(0,α⁻¹I)`, где `α>0` — точность априорного распределения.

Максимум апостериорной плотности (MAP) находится решением линейной системы.
В эталонном расчёте параметры интегрируются аналитически. Ответ записывается
через матрицу `C=σ²I+X_aug X_augᵀ/α` размера `n × n` в пространстве наблюдений:

$$
-\ln Z=\frac12\left[cn\ln(2\pi)+c\ln\det C+
\operatorname{tr}(Y^TC^{-1}Y)\right].
$$

Для одного выхода, столбца единичных входов, `y=(−0.5,0,0.5,1,1.5)`,
`σ²=0.75` и `α=0.6` ответ равен `6.85802314345658` nats.
Тест также охватывает несколько выходов, свободный член и случай `n<d`
с нормированным prior.

Равенство с точным интегралом выполняется для этой нормальной линейной модели
в точке MAP. Для произвольной сети KFAC-Laplace остаётся приближением.
В отдельном тесте сдвиг параметров `Δ` от MAP даёт прибавку
`tr(ΔᵀHΔ)/2=2.2734375` nats, где `H` — гессиан отрицательной логарифмической
апостериорной плотности. Так проверяется, что `check(...).ready` означает
пригодность входов для вычисления, а не подтверждение MAP-условия.

### Вариационная оценка: отклонение от evidence

В предыдущем примере с одним параметром апостериорное распределение (posterior)
имеет дисперсию
`v=(α+n/σ²)⁻¹` и среднее `m=v Σy_i/σ²`. Пусть приближающее распределение
`q=N(m_q,v_q)` имеет среднее `m_q` и дисперсию `v_q`.
Вариационная оценка `F(q)` складывается из ожидаемого отрицательного логарифма
правдоподобия и KL-дивергенции до prior:

$$
F(q)=E_q[-\ln p(y|\theta)]+KL(q\Vert prior)
=-\ln Z+\frac12\left[\frac{v_q+(m_q-m)^2}{v}-1+\ln\frac v{v_q}\right].
$$

Выражение после `−ln Z` — KL-дивергенция между `q` и точным posterior.
Если `q` совпадает с posterior, она равна нулю, а ответ составляет
`6.85802314345658` nats. При `m_q=m+0.4` и `v_q=1.5v` прибавка равна
`0.62860077927925` nats.

Подготовка входов методом Монте-Карло проверяется отдельно: `S=4096`,
seed `281`, KL до prior вычисляется аналитически. Допуск для ожидаемого
отрицательного логарифма правдоподобия (NLL) задан как
`8 sqrt(Var_q(NLL)/S)`. Здесь
`Var_q(NLL)=n²[2v_q²+4v_q(m_q−ȳ)²]/(4σ⁴)`, а `ȳ` — среднее наблюдений.
Этот допуск учитывает случайную ошибку усреднения.

### WBIC: ожидание при изменённой температуре

WBIC усредняет NLL по распределению, пропорциональному
`p(y|θ)^β p(θ)`, где `β=1/ln n`. В той же модели его дисперсия
`v_β=(α+βn/σ²)⁻¹`, а среднее `m_β=v_β βΣy_i/σ²`. Точное ожидание равно:

$$
WBIC=\frac12\left[n\ln(2\pi\sigma^2)+
\frac{\sum_i(y_i-m_\beta)^2+n v_\beta}{\sigma^2}\right].
$$

При `n=5` получается `6.25839790117077` nats. Две точки
`m_β±sqrt(v_β)` с равными весами точно интегрируют квадратичную NLL.
Тест передаёт эти готовые значения в WBIC и проверяет их усреднение.
Собственный сэмплер в этом расчёте не используется.

На этой конечной выборке WBIC отличается от `−ln Z=6.85802314345658`.
Разница ожидаема: WBIC здесь проверяется по формуле температурного ожидания.

### Последовательное кодирование

В последовательном, или prequential, коде модель предсказывает очередную метку
по уже раскрытым наблюдениям. Стоимость метки равна минус логарифму её
предсказанной вероятности. После подсчёта стоимости модель получает метку
и обновляется.

Для модели Бернулли с prior `Beta(1,1)` вероятность единицы перед шагом `i`
равна `p_i(1)=(1+s_{<i})/(2+i)`. Здесь `i=0,…,n−1` — число уже раскрытых меток,
`s_{<i}` — число единиц среди них, а `s` — число единиц во всей последовательности.
Через бета-функцию `B` полная длина записывается так:

$$
L=-\sum_i\ln p_i(y_i)=-\ln B(s+1,n-s+1).
$$

Для последовательности `0011` вероятности наблюдаемых меток меняются по шагам:

| Уже раскрытые метки | Следующая метка | Её вероятность |
| --- | ---: | ---: |
| Нет | 0 | 1/2 |
| 0 | 0 | 2/3 |
| 00 | 1 | 1/4 |
| 001 | 1 | 2/5 |

Произведение равно `B(3,3)=1/30`, поэтому длина составляет
`ln30=3.401197381662155` nats, или `4.906890595608519` bits.
Кодируется конкретная последовательность, поэтому биномиальный множитель
не нужен. Тесты перебирают все 16 последовательностей длины 4.

Блочный вариант фиксирует предсказатель внутри каждого блока и обновляет его
между блоками. Например, метки `1101` с границами `(1,3,4)` дают
`ln15=2.70805020110221` nats.

Повторное обучение на прошлых наблюдениях (replay) проверяется на двух вариантах.
Если повторная обработка не меняет достаточные статистики, байесовский код
сохраняется. Если повторения увеличивают вес старых наблюдений, последующие
предсказания меняются. Стоимость уже закодированных меток повторно не добавляется.

Отдельный пример проверяет `TemperatureScaler` при температуре `T=1`.
Вероятности правильных классов `3/4` и `4/5` должны сохраниться, а NLL равна
`−ln(3/4)−ln(4/5)`. Температура здесь задана, её подбор не проверяется.

### Двухчастный MDL

Двухчастный код складывает длину записи модели и стоимость данных при этой
модели. В тесте линейного классификатора веса класса 0 равны `(0,0)`,
веса класса 1 — `(0.4,1.5)`. Для входов `(1,0),(0,1),(1,1),(−1,1)`
и меток `1101` отрицательное логарифмическое правдоподобие равно
`Σ ln(1+exp((1−2y_i)wᵀx_i))=3.041150613781096` nats.
Здесь `w` — разность векторов весов двух классов.

После 2-битного квантования восстановленные веса класса 1 равны `(0.5,1.5)`,
а NLL составляет `3.115679960724055` nats. Для расчёта стоимости данных
используется именно восстановленная модель.

В текущем формате `L_model=8(13+H+B)` bits. Число `13` — размер фиксированной
части заголовка в байтах, `H` — длина JSON-заголовка, `B` — размер блоков тензоров.
В этом примере:

| Представление весов | `B`, байты |
| --- | ---: |
| Плотное | 32 |
| Разреженное | 17 |
| Квантованное | 1 |

Маски, метаданные и заполнение неполного байта входят в стоимость записи.
Полная оценка `L_total=L_model+NLL/ln2` выражена в битах. Тест проверяет
учёт размера выбранного формата. Это не универсальная минимальная длина
описания модели: заголовок может занимать больше места, чем экономит сжатие весов.

## Сжатие весов и граница риска

Преобразования весов, кодек и расчёт границы риска проверяются в
[test_analytical_codes_bounds.py](test_analytical_codes_bounds.py).

### Прореживание, низкий ранг и квантование

Преобразования проверяются на весах, для которых ошибка восстановления известна.
В таблице ошибка — сумма квадратов разностей исходных и восстановленных весов.

| Преобразование | Вход | Ожидаемый результат |
| --- | --- | --- |
| Прореживание по модулю веса | `(1,−2,3,4)`, удалить половину весов | `(0,0,3,4)`, ошибка `1²+2²=5` |
| Низкоранговое приближение | `diag(5,3,1)`, ранги `0,1,2,3` | Ошибка `Σ_{j>r} σ_j²`: `35,10,1,0` |
| Равномерное квантование | `(0,0.5,1,1.5,2,2.5,3)`, диапазон `[0,3]` | Шаг `Δ=3/(2^bits−1)`, при 2 битах ошибка `0.75` |

В низкоранговом примере `σ_j` — сингулярные значения матрицы. Сумма квадратов
отброшенных значений даёт минимальную ошибку заданного ранга в норме Фробениуса.
При квантовании значения на середине между уровнями округляются к чётному
индексу. Эти проверки измеряют искажение весов. Кодовая длина требует отдельного
учёта того, как преобразованные веса записаны.

### Arora: граница для сжатого классификатора

В примере задан вектор весов `(1.1,−1.1)ᵀ`, два вспомогательных вектора
`(1,1)ᵀ`, `(1,−1)ᵀ` и алфавит коэффициентов `{−2,−1,0,1,2}`.
Коэффициенты `(0,2.2)` округляются до `(0,2)`. Алгоритм Matrix-Project
восстанавливает веса `(1,−1)ᵀ`.

Для входов `X∈{−1,+1}` два компонента `WX` задают логиты классов 0 и 1,
а правильная метка равна `Y=1[X<0]`. Отступ — разность логита правильного
класса и логита другого класса. У исходной модели он равен `2.2` для обоих входов.
После сжатия максимальное изменение отдельного логита равно `0.1`.
Оно не превышает `γ/2` при пороге отступа `γ=1`. Обозначим число сохраняемых
коэффициентов через `q`, размер их алфавита через `r`, число наблюдений через `n`.
Параметр `δ` задаёт допустимую вероятность нарушения границы.
Величина `L̂_γ` — доля обучающих примеров, на которых отступ исходной модели
не превышает `γ`. Здесь она равна нулю, поскольку `2.2>γ`.

При `q=2`, `r=5`, `n=100`, `δ=0.05` граница риска сжатого классификатора равна:

$$
\widehat L_\gamma+\sqrt{\frac{q\ln r+\ln(1/\delta)}{2n}}
=\sqrt{\frac{2\ln5+\ln20}{200}}=0.17627546764116372.
$$

На двухточечном распределении с меткой `Y=1[X<0]` сжатый классификатор
ошибается с вероятностью `0`. Пример относится к Algorithm 1 и условной
Theorem 2.1 статьи Arora. Он не охватывает полную noise-stability Theorem 4.1.
Вспомогательные векторы, алфавит и семейство сжатых моделей должны быть выбраны
независимо от выборки. Это условие задаётся способом построения примера,
а не одним флагом в API.

<a id="integration"></a>

## Нормы, загрузка весов и производные

Эти примеры находятся в
[test_analytical_integration.py](test_analytical_integration.py).

Для матрицы `W=diag(3,−2,1)` известны все проверяемые характеристики:

| Характеристика | Значение |
| --- | ---: |
| Число элементов | 9 |
| L1-норма | 6 |
| Норма Фробениуса | `sqrt14` |
| Спектральная норма | 3 |
| Доля нулей | `6/9` |

Значения проверяются после сохранения и загрузки `state_dict`.
Ещё один пример использует два линейных слоя с весами `cI` и `I/c`, где
`I` — единичная матрица размера 2 и `c>0`. Их композиция всегда возвращает вход,
но общая L2-норма весов равна `sqrt(2c²+2/c²)` и зависит от `c`.
Поэтому норма весов характеризует выбранную параметризацию функции.

Для нормального правдоподобия при фиксированном векторе весов `w` тесты
сравнивают производные autograd с аналитическими выражениями
`∇(−2ℓ)=−2Xᵀ(y−Xw)/σ²` и `∇²(−2ℓ)=2XᵀX/σ²`.
Это проверка производных оценки в заданной точке. Веса не обязаны быть MLE.

<a id="tolerances"></a>

## Численные допуски

В зависимости от способа расчёта эталона `record_analytic` записывает одну
из трёх категорий сравнения:

| Категория | Как получен ожидаемый ответ |
| --- | --- |
| `exact` | По точной формуле заданной модели. Допуск учитывает округление чисел с плавающей точкой. |
| `finite_draw` | По переданному конечному набору значений. В WAIC это матрица логарифмов правдоподобия с поправкой `ddof=1`. |
| `approximation` | По аналитическому ожиданию, с отдельным допуском на случайную ошибку метода Монте-Карло. |

Численные допуски заданы в тестах для `float64` и `float32`. В примере
вариационной оценки отдельно указан допуск на ошибку метода Монте-Карло.

<a id="report"></a>

## Численный отчёт в JUnit

Чтобы сохранить вычисленные значения вместе с результатами pytest:

```bash
python -m pytest -q -k analytical -o junit_family=xunit1 --junitxml=build/analytical-results.xml
```

Функция `record_analytic` из [conftest.py](conftest.py) добавляет в свойства JUnit
записи `analytic_case`. В каждой записи есть сценарий, метод, ожидаемое
(`expected`) и полученное (`actual`) значения, абсолютная ошибка, единица,
допуски, формула эталона и результат сравнения. Запись создаётся до `assert`,
поэтому в отчёт попадают и неудачные численные сравнения. Папка `build/` игнорируется Git.
